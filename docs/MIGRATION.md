# Migration guide: 0.1.x development line to planned 1.0.0

This guide describes the intended stable API in the current working tree. The
package version is still `0.1.0`; v1.0.0 has not been approved, tagged, or
published. Do not treat this guide as evidence that a stable release exists.

## 1. Stop relying on automatic script re-execution

**Breaking change:** response scripts are no longer executed automatically.
The legacy `executeScripts` option is deprecated and ignored, even when set to
`true`.

Preferred options:

1. Move page behavior into your application entry point and initialize it
   through normal application code.
2. Use `boost:after-swap` / `boost:after-dom-update` to initialize components
   after navigation.
3. Only if absolutely necessary, supply `scriptHandler` and implement a
   strict allowlist for script sources and content. This is a privileged code
   execution boundary, not a safe way to execute arbitrary response scripts.

```ts
import { createBoost } from 'boost-html/core'

const boost = createBoost()
document.addEventListener('boost:after-swap', () => {
  initializePageWidgets()
})
boost.start()
```

## 2. Use the correct import for your initialization model

The root package entry auto-creates an instance in the browser. Importing named
exports from the root still triggers that side effect.

- Keep `import 'boost-html'` when automatic initialization is desired.
- Use `import { createBoost } from 'boost-html/core'` for manual lifecycle
  ownership and to avoid a second auto-created instance.
- `getBoost()` returns the root entry's auto-created instance or `null`.

## 3. Update form encoding expectations

**Breaking change:** POST forms without an explicit `enctype` use the native
`application/x-www-form-urlencoded` default instead of multipart encoding.

If your server expects multipart data, add the attribute explicitly:

```html
<form method="post" action="/upload" enctype="multipart/form-data">
  <input type="file" name="document">
  <button type="submit">Upload</button>
</form>
```

`text/plain` is also supported. Multipart boundaries are generated by Fetch;
do not set the `Content-Type` boundary manually. Submitter overrides
(`formaction`, `formmethod`, `formenctype`, and `formtarget`) are honored.

GET forms append fields to the query string. File inputs contribute file names,
not file contents, to GET submissions.

## 4. Handle failed POST requests explicitly

**Breaking change:** a failed boosted POST is not automatically re-submitted
as a native form. A network failure can occur after the server has processed a
request, so retrying may duplicate an order, payment, or other mutation.

Keep the safer default. If your application has an idempotency strategy and
intentionally wants native fallback, opt in:

```ts
createBoost({ fallbackToNativeForm: true })
```

Prefer idempotency keys and server-side deduplication before enabling this.

## 5. Return explicit HTML content types

Responses used for boosted navigation must declare `text/html` or
`application/xhtml+xml`. Missing content types are rejected. Ensure server
routes, reverse proxies, and error handlers set the correct response header.

## 6. Respect same-origin navigation and redirect checks

Programmatic `navigate()` accepts only same-origin HTTP(S) URLs. Redirects are
followed by Fetch, but the final response URL must remain same-origin HTTP(S)
and must not contain embedded URL credentials. Cross-origin links and forms
remain native browser navigations rather than being fetched and swapped.

If an endpoint intentionally redirects to another origin, use a normal link
or form submission rather than a boosted request.

## 7. Account for response size limits

The navigation response body limit is 2 MiB by default. Set
`maxResponseBytes` to a larger positive value for known larger documents, or
`0` to disable the navigation response limit. Prefetch still has an independent
2 MiB response cap.

## 8. Review cache and prefetch opt-in

Both prefetch and navigation cache are disabled by default. Before enabling
them:

- ensure cacheable responses are truly user-independent;
- return explicit `Cache-Control: public` and correct freshness / `Vary` headers;
- do not set cookies on responses marked public;
- exclude logout, checkout, account, tenant, and other sensitive routes;
- call `clearCache()` after external login/logout/account/tenant changes.

Browser-managed HttpOnly cookies are not visible to JavaScript. A response
that varies by cookie must not be marked public.

## 9. Review response HTML and CSP integration

The library filters common active-content surfaces, but is not a general HTML
sanitizer. Server-rendered user-generated HTML must be sanitized before it is
returned. Under strict Trusted Types enforcement, provide a host-owned
`createHTML` policy that returns TrustedHTML. Do not use a permissive policy as
a workaround.

The progress stylesheet accepts a CSP `nonce`. If you use `scriptHandler`, it
must validate scripts and apply the host's CSP policy. See the
[security audit](./SECURITY.md).

## 10. Review selectors and lifecycle hooks

- `formSelector` now determines which forms are eligible for interception.
- `linkSelector` determines which links are eligible for interception.
- `target` must resolve in both the live and response documents.
- `swapHandler` and `morphAdapter` must update synchronously.
- `boost:before-request`, `boost:before-swap`, and
  `boost:before-dom-update` are cancelable.
- Canceling a cancelable `boost:error` prevents hard-navigation fallback.

## 11. Upgrade checklist

- [ ] Replace `executeScripts: true` usage with application-owned behavior or a
      reviewed `scriptHandler` allowlist.
- [ ] Import `boost-html/core` when creating a manually managed instance.
- [ ] Verify POST form encoding and explicitly set `enctype` where needed.
- [ ] Confirm failed POST requests are safe without automatic retry.
- [ ] Set explicit HTML content types on all boosted endpoints.
- [ ] Remove cross-origin routes from boosted navigation scopes.
- [ ] Check response sizes against the 2 MiB default.
- [ ] Keep prefetch/cache disabled until server cache directives are correct.
- [ ] Add `createHTML` and `nonce` for the application's CSP / Trusted Types
      deployment policy.
- [ ] Run unit tests and the Chromium / Firefox / WebKit browser suite.
